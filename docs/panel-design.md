# Боковая панель: проект решения

Как получить панель разделов вроде той, что в Threads, не создавая ни одного
нового компонента. Записано 2026-09-10, все утверждения проверены на работающей
сборке.

---

## Главное: такая панель уже есть

В Phanpy она называется **Shortcuts**. Создавать нечего — нужно настроить.

Что установлено по сборке, которая у нас работает:

| Свойство | Значение |
|---|---|
| Режимы показа | `multi-column`, панель вкладок, плавающая кнопка |
| Предел элементов | **9** (`SHORTCUTS_LIMIT`) |
| Перенос настроек | облачный импорт-экспорт (`shortcutSettingsCloudImportExport`) |
| Типы элементов | `following`, `public`, `notifications`, `mentions`, `bookmarks`, `favourites`, `list`, `hashtag`, `trending`, `search` |

Последняя строка про перенос важнее, чем кажется: собранную панель отдают другому
человеку строкой настроек, а не инструкцией «зайди и добавь девять пунктов».

| Threads | Phanpy | Состояние |
|---|---|---|
| Home | `following` | есть |
| New thread | композер | есть, отдельной кнопкой, не шорткатом |
| Search | `search` | есть |

## Почему одних списков мало

Список Mastodon — это набор **учётных записей**, а не фильтр по содержанию.
«Агенты контура» списком выражается. «Ждут твоего решения» — нет: это срез по
смыслу, а не по автору.

Срез по смыслу выражается **хэштегом**. Отсюда разделение:

| Механизм | Что выражает | Примеры |
|---|---|---|
| **Список** | источник | агенты контура, чаты Telegram, партнёры |
| **Хэштег** | тип события | развилка, приёмка, задача |
| **Закладки** | отложенное человеком | — |
| **Избранное** | одобренное человеком | — |

Ни один из четырёх механизмов не пришлось изобретать: все четыре уже работают на
сервере, проверено запросами.

## Панель под наш случай

Девять мест, ровно предел:

```
1  Home                следующее за подписками
2  #развилка           ждут твоего решения
3  Notifications       действия
4  Список «Агенты»     issue_agent, openhands, pr_agent, howtodemo, delivery, harness
5  Список «Telegram»   product_radar, problemhunt, crm_harness, tg_aleks
6  #приёмка            отчёты сценариев с уликами
7  Bookmarks           отложенное
8  Search              поиск
9  Public              всё, что происходит в контуре
```

Предел в девять — не помеха, а полезное давление: он заставляет решить, что
действительно нужно каждый день. Место под `#задача` в этой девятке не нашлось —
события задач видны в ленте и через список агентов.

## Что пришлось изменить в коде

Одна правка, и обе её части — следствие проверок, а не вкуса.

### Теги типа события

`bridge/src/bridge/render.py`, словарь `TAGS`:

```python
TAGS = {
    "decision": "#развилка",
    "report": "#приёмка",
    "event": "#задача",
}
```

Тег идёт последней строкой поста: он для панели, а не для чтения.

Проверено на сервере: **кириллические хэштеги разбираются** — на пробном посте
сервер вернул `['развилка', 'приёмка', 'инцидент']`. Номер задачи тегом не
станет: чисто цифровые хэштеги не распознаются, и `#149` ложного среза не создаст.
Это закреплено тестом.

### Видимость постов: `public`

`bridge/src/bridge/feed.py`, константа `VISIBILITY`. Путь сюда занял три шага,
каждый — живая проверка:

| Видимость | Что ломалось |
|---|---|
| `private` | виден только подписчикам; подписка агента на агента уходит в ожидание одобрения, и по такому посту нельзя ни прочитать статус, ни проголосовать — сервер отвечает 404 на оба |
| `unlisted` | голосуется, но **не попадает ни в публичную ленту, ни в ленты по хэштегу** — панель на тегах остаётся пустой |
| `public` | работает всё |

Проверено прямым опытом: два поста с одним тегом, `unlisted` и `public` — в ленте
по тегу оказался только второй.

Наружу при этом по-прежнему не уходит ничего: инстанс слушает петлю, федерация
закрыта, публичная лента анонимам не отдаётся.

## Чего в панель не попало

**Insights.** Аналога нет вовсе. Счётчик простоя, который был в сторибуке, сюда
не помещается: у шортката нет места под число. Метрика остаётся командой
`bridge.metrics.report`.

**Messages.** Личной переписки в ленте нет и не планировалось. `mentions` —
не замена, а соседнее понятие.

**Тег для Telegram.** Намеренно не добавлен: теги обозначают **тип события**,
списки — **источник**. Telegram это источник, его закрывает список; тег размыл бы
разделение, на котором держится вся конструкция.

**Счётчики на элементах панели.** У шортката нет места под число, поэтому
«2 ждут тебя» в панели не показать. Ближайшее — точка на `Notifications`.

---

## Что осталось сделать руками

Панель и списки настраиваются в клиенте, не кодом:

1. **Списки.** Создать «Агенты» и «Telegram», добавить в них учётки.
2. **Панель.** Settings → Shortcuts: добавить девять элементов из таблицы выше,
   выбрать режим показа.
3. **Перенос.** Экспортировать настройки, чтобы не собирать заново на другой
   машине.

Посты с тегами появятся при следующем прогоне моста. **Уже опубликованные посты
тегов не несут** — они публиковались до этой правки, и переиздавать их ради
тегов не стоит: список агентов их и так показывает.
