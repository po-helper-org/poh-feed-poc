# HowToDemo — Лента контура (PoC)

Сценарий приёмки всего PoC целиком. Переписан 2026-08-26 после сквозного обзора
ветки: за десять задач правок код ушёл вперёд, и прежний сценарий провалился бы
на половине шагов из-за себя, а не из-за кода.

**Что демонстрируем:** человек закрывает развилку агента одним касанием в ленте,
и система продолжает работу — без захода в GitHub, Temporal и `docker logs`.

**Что НЕ демонстрируем:** доступ с телефона, пуш-уведомления, работу без
ноутбука, вторую пару рук, перенос на сервер.

---

## Условия прогона

| Что | Значение |
|---|---|
| Где крутится | ноутбук, `~/projects/poh-org/poh-feed-poc` |
| Лента | GoToSocial `0.21.2`, API `http://127.0.0.1:8080` |
| Клиент | Phanpy `http://127.0.0.1:8083`, инстанс `https://feed.localhost:8443` |
| Мост | `bridge`, Python |
| Связь с системой | **только GitHub API** |
| Изменений в системе | **ноль** |

**Почему нет ни SSH, ни Temporal.** Снято с кода системы: ожидание решения видно
меткой `needs-human:triage`, фаза — меткой `phase:*`, а решение доставляется
постановкой одной из пяти меток, которую вебхук системы превращает в сигнал
воркфлоу.

**Обязательные переменные в `.env`** (см. `.env.example`, там каждая объяснена):
`FEED_TOKEN_*` для шести агентов, `GITHUB_TOKEN`, `BRIDGE_REPOS`. Последняя
намеренно без значения по умолчанию: мост, запущенный без настройки, не должен
писать в чей-то рабочий репозиторий.

**Предусловие, которое проверяется шагом, а не подразумевается:** в обслуживаемом
репозитории есть задача с меткой `needs-human:triage` и меткой фазы, для которой
у ленты есть вопрос (`classified`, `ready-for-dev` или `duplicate`).

---

## Ограничение приёмки, известное заранее

**Часть шагов принимается только человеческим глазом.** Проверяемая гипотеза —
«механика читается и работает руками» — не подтверждается кодом возврата. Такие
шаги помечены `ГЛАЗАМИ`, они обязательны и автоматически не зачитываются.

Всё, что можно проверить кодом, проверяется кодом.

---

## Сценарий

### Акт 1. Лента живёт и наружу не смотрит

**1. Инстанс отвечает.**
```bash
curl -fsS http://127.0.0.1:8080/api/v1/instance | python3 -c 'import sys,json;print(json.load(sys.stdin)["uri"])'
```
Ожидаемо: печатается адрес инстанса, код 0.

**2. Ни одного публичного порта.**
```bash
docker compose ps --format '{{.Name}} {{.Ports}}'
```
Ожидаемо: у каждой строки адрес `127.0.0.1`. Появление `0.0.0.0` — провал.

**3. Федерация закрыта.**
```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  "http://127.0.0.1:8080/api/v2/search?q=https://mastodon.social/@Gargron&resolve=true"
```
Ожидаемо: `401`, `403`, `404` или `422`. Код `200` означает, что инстанс пошёл во
внешнюю сеть — **провал сценария целиком**, остальные шаги не имеют значения.
Любой другой код тоже провал: проверка недостоверна.

**4. У ленты есть предел памяти.**
```bash
docker inspect poh-feed --format '{{.HostConfig.Memory}}'
```
Ожидаемо: значение не `0`.

**5. Лимиты под механику применились.**
```bash
curl -fsS http://127.0.0.1:8080/api/v1/instance | python3 -c '
import sys,json;c=json.load(sys.stdin)["configuration"]
print("символов:",c["statuses"]["max_characters"],
      "| вариантов опроса:",c["polls"]["max_options"],
      "| вложений:",c["statuses"]["max_media_attachments"])'
```
Ожидаемо: `20000`, `4`, `6`.

**6. Шесть агентов и человек заведены.**
```bash
docker exec poh-feed /gotosocial/gotosocial --config-path /gotosocial/config.yaml \
  admin account list 2>/dev/null | tail -n +2
```
Ожидаемо: семь строк — `issue_agent`, `openhands`, `pr_agent`, `howtodemo`,
`delivery`, `harness`, `aleks`.

### Акт 2. Три инструмента ветки

**7. Опрос, свёртка и вложения публикуются.**
```bash
./scripts/smoke_tools.sh
```
Ожидаемо: три `OK`, затем код ответа на попытку совместить опрос и вложение —
**не** 200. Этот отказ подтверждает, что улики и вопрос по ним обязаны быть
двумя постами.

Скрипт заодно рисует `/tmp/shot1.png` и `/tmp/shot2.png`, которые понадобятся в
акте 5.

**8. `ГЛАЗАМИ` Инструменты работают так, как задумано.**
Открыть `http://127.0.0.1:8083`, указать инстанс `feed.localhost:8443`, войти как
`aleks@feed.local`, найти три поста из шага 7.

Ожидаемо:
- опрос показан вариантами, голос принимается, счётчик растёт;
- свёртка видна одной строкой, разворачивается нажатием, Markdown отрисован
  заголовками;
- отчёт показывает две картинки сеткой, картинка открывается во весь экран.

**Зачесть этот шаг без человека нельзя.**

### Акт 3. Развилка замыкается на системе

Главный акт. Всё остальное — обвязка вокруг него.

**9. Настройки на месте.**
```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/python -c \
'from bridge.config import Settings; s=Settings.load(); print("репозитории:", s.repos, "| пауза:", s.cycle_seconds)'
```
Ожидаемо: печатается список репозиториев и пауза. Отказ с явной ошибкой про
`GITHUB_TOKEN` или `BRIDGE_REPOS` означает, что переменные не заданы, — это и есть
задуманное поведение, задайте их и повторите.

**10. Есть задача, ждущая человека, и лента знает, что ей предложить.**
```bash
gh issue list --repo <owner/repo> --label needs-human:triage --state open \
  --json number,title,labels --limit 60 > /tmp/waiting.json

cd bridge && .venv/bin/python - <<'PY'
import json, sys
sys.path.insert(0, "src")
from bridge.render import question_for_phase

rows = json.load(open("/tmp/waiting.json"))
for row in rows:
    names = [label["name"] for label in row["labels"]]
    phase = next((n[len("phase:"):] for n in names if n.startswith("phase:")), None)
    mark = "+" if phase and question_for_phase(phase) else " "
    print(f'{mark} #{row["number"]:<5} {str(phase):<14} {row["title"][:50]}')
print("всего ждут человека:", len(rows))
PY
```
Ожидаемо: хотя бы одна строка со знаком `+`. Если знаков `+` нет вовсе — лента
предложить нечего, и акт 3 проверять не на чем: довести живую задачу до фазы
`classified`, `ready-for-dev` или `duplicate`.

**11. Первый обход публикует развилки.**

> **Осторожно, первый обход шумный.** Кроме развилок он опубликует ветки по
> последним задачам репозитория — до двадцати постов разом. Это штатно: цикл
> событий видит задачи впервые. На второй раз он молчит.

```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/feed-bridge --once
```
Ожидаемо: строка вида
`развилок: N, решений: 0, событий GitHub: M, снято меток: 0`, где `N` — число
задач со знаком `+` из шага 10.

Строка печатается только если хоть один счётчик ненулевой. Полная тишина при
непустом списке из шага 10 — провал.

**12. `ГЛАЗАМИ` Пост читается и голосуется.**
В Phanpy найти новый пост от `issue_agent` по нужной задаче.

Ожидаемо: виден вопрос по фазе задачи, варианты, координаты `репозиторий · #номер`
и строка про то, что без ответа система уводит задачу в эскалацию.

Проголосовать. Для задачи в фазе `duplicate` честный ответ — **«Подтверждаю
дубликат»**, если задача действительно дубликат.

> **Не голосуй за «Это баг»** на задаче в фазе `classified`: путь `bug-me` в
> системе не реализован и роняет прогон. Пост об этом предупреждает — проверь,
> что предупреждение видно.

**13. Голос доехал до системы.**
```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/feed-bridge --once
```
Ожидаемо: `решений: 1` в счётчиках.

**14. Метка решения появилась на задаче.**
```bash
gh issue view <N> --repo <owner/repo> --json labels \
  | python3 -c 'import sys,json;print([l["name"] for l in json.load(sys.stdin)["labels"]])'
```
Ожидаемо: среди меток есть выбранная (`confirm-duplicate`, `not-duplicate`,
`research-me`, `bug-me` или `build-me` — та, что соответствует нажатому варианту).

**15. Система приняла решение и поехала дальше.**
Повторить команду шага 14 через минуту-другую.

Ожидаемо: метка `needs-human:triage` исчезла, метка `phase:*` сменилась.

**Это и есть единственная непроверенная гипотеза всего PoC.** Из кода системы
следует, что постановка метки доставляет решение уже идущему прогону — вебхук
зовёт «сигнал вместе со стартом». Но это свойство сервера Temporal, а не их кода.
Если ожидание не снялось — смотреть логи вебхука на сервере, а не чинить мост.

**16. След остался в истине.**
Открыть задачу на GitHub.
Ожидаемо: комментарий «Решение принято через ленту контура: **вариант**».

### Акт 4. Одна задача — одна ветка

**17. Повторный обход не плодит постов.**
```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/feed-bridge --once
```
Ожидаемо: `развилок: 0` и `событий GitHub: 0` — либо полная тишина, если все
счётчики нулевые.

**18. `ГЛАЗАМИ` Ветка читается целиком.**
В Phanpy открыть ветку задачи.

Ожидаемо: один корневой пост, под ним ответы по времени. Не россыпь отдельных
постов об одной и той же задаче.

### Акт 5. Отчёт приёмки

**19. Улики и продолжение — два поста.**
```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/python - <<'PY'
from pathlib import Path
from bridge.config import Settings
from bridge.feed import Feed
from bridge.mapping import Mapping
from bridge.pump import publish_report
s = Settings.load()
print(publish_report(
    Feed.from_settings(s), Mapping(s.db_path),
    s.repos[0], 149,
    passed=4, total=5, seconds=96,
    blocked=["шаг 4 — браузер на стенде не поднять по памяти"],
    shots=[Path("/tmp/shot1.png"), Path("/tmp/shot2.png")],
))
PY
```
Ожидаемо: кортеж из двух непустых идентификаторов — отчёта и ответа.

**20. Расхождение в счёте объяснено целиком.**
Ожидаемо: в тексте отчёта есть строка «Не проверял: шаг 4 — браузер…».

Проверить заодно, что отчёт не умалчивает о провалившихся шагах:
```bash
cd bridge && .venv/bin/python -c "
import sys; sys.path.insert(0,'src')
from bridge.render import render_report
print(render_report(passed=3, total=5, seconds=96, blocked=[]))"
```
Ожидаемо: строка про провалившиеся шаги. Отсутствие объяснения при
`passed < total` — провал: пустая проверка неотличима от пройденной, если о ней
промолчать.

**21. `ГЛАЗАМИ` Отчёт читается за две секунды.**
Ожидаемо: в ветке виден пост со скриншотами, а следом отдельный ответ,
называющий непроверенные шаги поимённо. **Опроса под отчётом быть не должно** —
его варианты не отображались бы ни в одну метку системы.

### Акт 6. Повтор, уборка и отказ

**22. Метка ставится ровно один раз.**
```bash
cd bridge && .venv/bin/pytest tests/test_pump.py -k "once or idempot" -v
```
Ожидаемо: PASS.

**23. Залипшая метка решения убирается — но только когда ожидание снято.**

Система метку решения **никогда не снимает сама**. Пока она висит, повторная её
постановка не породит события GitHub, и следующая развилка той же фазы молча не
сработает.

Порядок проверки важен:

1. сразу после шага 13 прогнать обход ещё раз — метка решения обязана **остаться**
   (`снято меток: 0`), потому что задача ещё ждёт;
2. дождаться, пока система снимет `needs-human:triage` (шаг 15);
3. прогнать обход снова.

Ожидаемо на третьем шаге: `снято меток: 1`, и метки решения на задаче больше нет.

Убирать метку раньше времени — тот самый дефект, который сквозной обзор нашёл в
уборке: она помечала задачу обработанной в тот же проход, когда снимать было
нечего, и больше к ней не возвращалась.

**24. Отказ GitHub несёт причину и не роняет обход.**
```bash
cd bridge && set -a && source ../.env && set +a && GITHUB_TOKEN=явно_негодный \
  .venv/bin/feed-bridge --once
```
Ожидаемо: строки вида `развилки: обход не удался: …` либо
`обход: github: … не удался: …` — **с текстом ошибки от GitHub**, и процесс
завершился штатно, а не трейсбеком. Сообщение без причины — провал.

### Акт 7. Простой посчитан

**25. Метрика есть, и она не умалчивает.**
```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/python -c \
'from bridge.config import Settings; from bridge.mapping import Mapping; from bridge.metrics import report; print(report(Mapping(Settings.load().db_path)))'
```
Ожидаемо: строка вида
`Простой контура — 1 решение (медиана простоя: 6.0 мин, худший случай: 6.0 мин), без ответа: 1 развилка.`

Число «без ответа» обязано присутствовать. Метрика, показывающая только
решённые развилки, врёт умолчанием: красивая медиана по быстрым решениям ничего
не говорит о тех, что остались без ответа вовсе.

## Что считается провалом

- Любой машинный шаг не совпал с ожидаемым.
- Шаг с пометкой `ГЛАЗАМИ` зачтён без человека.
- Шаг 3 вернул `200` или непонятный код: проверка федерации недостоверна. Провал
  сценария целиком.
- Метка решения поставлена дважды на одну развилку.
- На одну развилку создано больше одного поста.
- При `passed < total` отчёт умолчал о недостающих шагах.
- Под постом есть кнопка, нажатие которой ничего не делает в системе.
- Отказ сообщил код без текста ошибки.
- Залипшая метка решения не убрана после снятия ожидания.
- Метрика показала медиану, не назвав число развилок без ответа.

## Чего этот сценарий не проверяет и почему

- **Доступ с телефона** — вне PoC, требует tailnet и сертификата.
- **Работу без ноутбука** — мост спит вместе с ним; в эти часы метрика простоя
  занижена, считать её только по активным окнам.
- **Нагрузку** — один человек и несколько агентов, потолок не исследуется.
- **Задачи в фазах, из которых система не выводит меткой.** Их большинство:
  на 2026-08-26 из 24 задач, ждущих человека, вопрос у ленты был только к трём.
  Остальные стоят в фазах `failed` и `escalated`, выход из которых в коде системы
  есть, а производителя сигнала для него нет. Лента о них молчит — это открытый
  вопрос продукта, а не дефект моста.
