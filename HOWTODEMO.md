# HowToDemo — Лента контура (PoC)

Сценарий приёмки всего PoC целиком.

**Что демонстрируем:** человек закрывает развилку агента одним касанием в ленте,
и контур продолжает работу — без захода в GitHub, Temporal и `docker logs`.

**Что НЕ демонстрируем:** доступ с телефона, пуш-уведомления, работу без
ноутбука, вторую пару рук, перенос на стенд. Всё это — после подтверждения PoC.

---

## Условия прогона

| Что | Значение |
|---|---|
| Где крутится | ноутбук, `~/projects/poh-org/poh-feed-poc` |
| Лента | GoToSocial `0.21.2`, API на `http://127.0.0.1:8080` |
| Клиент | Phanpy на `http://127.0.0.1:8083`, инстанс `https://feed.localhost:8443` |
| Мост | `bridge`, Python |
| Связь с контуром | **только GitHub API** |
| Изменений в контуре | **ноль** |

**Почему нет ни SSH, ни Temporal.** Снято с кода контура: ожидание решения видно
меткой `needs-human:triage`, фаза — меткой `phase:*`, а решение доставляется
постановкой одной из пяти меток, которую вебхук контура превращает в сигнал
воркфлоу. Прямой доступ к Temporal внешнему инструменту не нужен.

**Предусловие, которое проверяется шагом, а не подразумевается:** в
демо-репозитории существует задача с меткой `needs-human:triage` и меткой
`phase:*`. Без неё акт 3 проверяет пустоту и врёт об успехе.

---

## Ограничение приёмки, известное заранее

**Часть шагов принимается только человеческим глазом, и это не лень, а свойство
задачи.** Проверяемая гипотеза звучит как «механика читается и работает
руками» — её нельзя подтвердить кодом возврата. Такие шаги помечены `ГЛАЗАМИ`;
они обязательны и не могут быть зачтены автоматически.

Обратное тоже верно: всё, что можно проверить кодом, проверяется кодом. Вердикт
по машинным шагам считает скрипт, а не впечатление.

---

## Сценарий

### Акт 1. Лента живёт и наружу не смотрит

**1. Инстанс отвечает.**
```bash
curl -fsS http://127.0.0.1:8080/api/v1/instance | python3 -c 'import sys,json;print(json.load(sys.stdin)["uri"])'
```
Ожидаемо: печатается адрес инстанса, код 0.

**2. Ни одного публичного порта.**
```bash
docker compose ps --format '{{.Name}} {{.Ports}}'
```
Ожидаемо: у каждой строки адрес `127.0.0.1`. Появление `0.0.0.0` — провал.

**3. Федерация закрыта.**
```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  "http://127.0.0.1:8080/api/v2/search?q=https://mastodon.social/@Gargron&resolve=true"
```
Ожидаемо: код **не** 200. Двухсотый ответ означает, что инстанс пошёл во
внешнюю сеть — провал сценария целиком, дальше не идти.

**4. У ленты есть предел памяти.**
```bash
docker inspect poh-feed --format '{{.HostConfig.Memory}}'
```
Ожидаемо: значение не `0`.

**5. Лимиты под механику применились.**
```bash
curl -fsS http://127.0.0.1:8080/api/v1/instance | python3 -c '
import sys,json;c=json.load(sys.stdin)["configuration"]
print("символов:",c["statuses"]["max_characters"],
      "| вариантов опроса:",c["polls"]["max_options"],
      "| вложений:",c["statuses"]["max_media_attachments"])'
```
Ожидаемо: `20000`, `4`, `6`.

**6. Шесть агентов и человек заведены.**
```bash
docker exec poh-feed /gotosocial/gotosocial --config-path /gotosocial/config.yaml \
  admin account list 2>/dev/null | tail -n +2
```
Ожидаемо: семь строк — `issue_agent`, `openhands`, `pr_agent`, `howtodemo`,
`delivery`, `harness`, `aleks`.

### Акт 2. Три инструмента ветки

**7. Опрос, свёртка и вложения публикуются.**
```bash
./scripts/smoke_tools.sh
```
Ожидаемо: три `OK`, затем код ответа на попытку совместить опрос и вложение —
**не** 200. Этот отказ подтверждает, что улики и вопрос по ним обязаны быть
двумя постами.

**8. `ГЛАЗАМИ` Инструменты работают так, как задумано.**
Открыть `http://127.0.0.1:8083`, указать инстанс `feed.localhost:8443`, войти
под `aleks`, найти три поста из шага 7.

Ожидаемо:
- опрос показан вариантами, голос принимается, счётчик растёт;
- свёртка видна одной строкой, разворачивается нажатием, Markdown отрисован
  заголовками разделов;
- отчёт показывает две картинки сеткой, картинка открывается во весь экран.

**Зачесть этот шаг без человека нельзя.**

### Акт 3. Развилка замыкается на контуре

Главный акт. Всё остальное — обвязка вокруг него.

**9. Задача, ждущая человека, стала постом с опросом.**

Предварительно убедиться, что такая задача есть:
```bash
gh issue list --repo po-helper-org/poh-demo-checkout --label needs-human:triage --json number,labels
```
Ожидаемо: хотя бы одна задача, и у неё есть метка `phase:*`. Пусто — довести
живую задачу контура до ожидания решения, иначе следующие шаги проверяют пустоту.

```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/feed-bridge --once
```
Ожидаемо: строка вида `развилок: 1, решений: 0, снято меток: 0`.

**10. `ГЛАЗАМИ` Пост читается и голосуется.**
В Phanpy найти новый пост от `issue_agent`.

Ожидаемо: виден вопрос по фазе задачи, варианты, координаты `репозиторий · #номер`
и строка «Без ответа контур уводит задачу в эскалацию по своему сроку».
Проголосовать за **«Разобрать аналитикой»**.

> **Не голосуй за «Это баг».** Путь `bug-me` в контуре не реализован и роняет
> прогон. Пост сам об этом предупреждает — проверь, что предупреждение видно.

**11. Голос доехал до контура.**
```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/feed-bridge --once
```
Ожидаемо: строка вида `развилок: 0, решений: 1, снято меток: 0`.

**12. Метка решения появилась на задаче.**
```bash
gh issue view <N> --repo po-helper-org/poh-demo-checkout --json labels \
  | python3 -c 'import sys,json;print([l["name"] for l in json.load(sys.stdin)["labels"]])'
```
Ожидаемо: среди меток есть `research-me`.

**13. Контур принял решение и поехал дальше.**
Повторить команду шага 12 через минуту-другую.

Ожидаемо: метка `needs-human:triage` исчезла, фаза `phase:*` сменилась.

Это и есть подтверждение того, что постановка метки доставляет решение **уже
идущему** прогону. Из кода контура это следует, но серверным поведением
Temporal не гарантировано — данный шаг и есть его живая проверка. Если решение
не доехало, смотреть логи вебхука на стенде, а не чинить мост.

**14. След остался в истине.**
Открыть задачу на GitHub.
Ожидаемо: комментарий «Решение принято через ленту контура: **вариант**».

### Акт 4. Одна задача — одна ветка

**15. Повторный обход не плодит постов.**
```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/feed-bridge --once
```
Ожидаемо: `развилок: 0`.

**16. `ГЛАЗАМИ` Ветка читается целиком.**
В Phanpy открыть ветку задачи.

Ожидаемо: один корневой пост, под ним ответы по времени. Не россыпь отдельных
постов об одной и той же задаче.

### Акт 5. Отчёт приёмки

**17. Улики и продолжение — два поста.**
```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/python - <<'PY'
from pathlib import Path
from bridge.config import Settings
from bridge.feed import Feed
from bridge.mapping import Mapping
from bridge.pump import publish_report
s = Settings.load()
print(publish_report(
    Feed.from_settings(s), Mapping(s.db_path),
    "po-helper-org/poh-demo-checkout", 149,
    passed=4, total=5, seconds=96,
    blocked=["шаг 4 — браузер на стенде не поднять по памяти"],
    shots=[Path("/tmp/shot1.png"), Path("/tmp/shot2.png")],
))
PY
```
Ожидаемо: кортеж из двух непустых идентификаторов — отчёта и ответа.

**18. Незачтённый шаг назван словами.**
Ожидаемо: в тексте отчёта присутствует «Не проверял: шаг 4 — браузер…».
Отсутствие этой строки при `passed < total` — провал: пустая проверка
неотличима от пройденной, если о ней промолчать.

**19. `ГЛАЗАМИ` Отчёт читается за две секунды.**
Ожидаемо: в ветке виден пост со скриншотами, а следом отдельный ответ,
называющий непроверенные шаги поимённо. **Опроса под отчётом быть не должно** —
его варианты не отображались бы ни в одну метку контура, и голос ничего бы
не сделал.

### Акт 6. Повтор, уборка и отказ

**20. Метка ставится ровно один раз.**
```bash
cd bridge && .venv/bin/pytest tests/test_pump.py::test_label_is_put_once -v
```
Ожидаемо: PASS.

**21. Залипшая метка решения убирается.**
После того как контур снял `needs-human:triage`, прогнать мост ещё раз и
повторить команду шага 12.

Ожидаемо: строка `снято меток: 1`, и метки `research-me` на задаче больше нет.

Это не косметика: контур метку решения не снимает никогда, а пока она висит,
повторная её постановка не породит события GitHub — и следующая развилка той же
фазы молча не сработает.

**22. Отказ GitHub несёт причину и не роняет обход.**
```bash
cd bridge && set -a && source ../.env && set +a && GITHUB_TOKEN=явно_негодный \
  .venv/bin/feed-bridge --once
```
Ожидаемо: строка `обход не удался:` **с текстом ошибки от GitHub** (код и
сообщение), процесс завершился штатно, а не трейсбеком. Сообщение без причины —
провал.

### Акт 7. Простой посчитан

**23. Метрика есть и она осмысленна.**
```bash
cd bridge && set -a && source ../.env && set +a && .venv/bin/python -c \
'from bridge.config import Settings; from bridge.mapping import Mapping; from bridge.metrics import report; print(report(Mapping(Settings.load().db_path)))'
```
Ожидаемо: `Простой контура — решений: N, медиана простоя: X мин, худший
случай: Y мин.` при N ≥ 1.

---

## Что считается провалом

- Любой машинный шаг не совпал с ожидаемым.
- Шаг с пометкой `ГЛАЗАМИ` зачтён без человека.
- Шаг 3 вернул 200: инстанс пошёл во внешнюю сеть. Это провал сценария целиком,
  остальные шаги не имеют значения.
- Метка решения поставлена дважды на одну развилку.
- На одну развилку создано больше одного поста.
- При `passed < total` отчёт умолчал о незачтённом шаге.
- Под постом есть кнопка, нажатие которой ничего не делает в контуре.
- Отказ GitHub сообщил код без текста ошибки.
- Залипшая метка решения не убрана — следующая развилка той же фазы не сработает.

| Что | Где |

## Чего этот сценарий не проверяет и почему

- **Доступ с телефона** — вне PoC, требует tailnet и сертификата.
- **Работу без ноутбука** — мост спит вместе с ним; в эти часы метрика простоя
  занижена, считать её только по активным окнам.
- **Нагрузку** — один человек и несколько агентов, потолок не исследуется.
- **Перенос на стенд** — на нём свободно около гигабайта, свопа нет и рядом
  чужой прод; вопрос ставится только после подтверждения механики.
